### Regles principals
1. El parent model és la base: no redisseny total.
2. Canvis incrementals, justificats i fàcils d'atribuir; màxim 1 canvi estructural menor i 1-2 refinaments.
3. Evita repetir patrons de la família sense variació real, especialment si el context mostra saturació sense breakthrough.
4. Explica clarament què canvies respecte al parent, quin mecanisme concret hauria d'ajudar a millorar SL/TB i/o `decision_score` versus referències fortes de família, i quines serien les següents variants.
5. Prioritza estabilitat build/compile/smoke-fit.
6. Si dubtes d'schema o consistència, simplifica; si dubtes de competitivitat, escull el refinament amb més potencial explicable.
7. Si una proposta implica salt arquitectònic fort, NO és evolution: reconduir-la a mutació incremental.

### Procés mental recomanat
1. Llegeix primer el `parent_model`, `family_models`, `family_metrics_summary` i `genealogy_case_studies` abans de dissenyar res.
2. Formula una hipòtesi principal breu i atribuïble: quin canvi hauria de millorar SL/TB o decision_score.
3. Decideix explícitament què mantens del parent perquè ja funciona, i què canvies perquè sospites que és el coll d'ampolla.
4. Dissenya la mutació més petita possible que permeti validar aquesta hipòtesi.
5. Abans de retornar, revisa si el JSON final ajuda una futura generació a entendre què s'ha provat i com continuar l'experiment.

### Camps permesos dins `training_config`
- `batch_size` (int): mostres per gradient step
- `epochs` (int): nombre maxim d'epochs
- `validation_split` (float): fraccio per validacio
- `early_stopping_patience` (int): epochs sense millora per parar
- `reduce_lr_patience` (int): epochs sense millora per reduir lr
- `reduce_lr_factor` (float): factor de reduccio de lr
- `min_lr` (float): lr minim
- `restore_best_weights` (bool): restaurar millors pesos
- `initial_learning_rate` (float): lr inicial
- `optimizer` (string): nom de l'optimitzador
- `seed` (int): llavor aleatoria
- `target_metric` (string): metrica per early stopping
- `target_metric_mode` (string): min o max
- `max_training_minutes` (int): temps maxim d'entrenament
- `soft_max_epochs` (int): cap maxima d'epochs (soft)
- `business_metric_sl_weight` (float): pes SL a la metrica de negoci
- `business_metric_tb_weight` (float): pes TB a la metrica de negoci
- `business_min_relative_improvement` (float): millora minima relativa
- `business_improvement_window` (int): finestra per estancament

### Guardrails d'arquitectura
- `architecture_definition` obligatori.
- `used_inputs` obligatori i no buit.
- `branches` obligatori i no buit.
- `output_heads` obligatori i no buit.
- `merges` opcional, però si existeix ha de ser llista.
- Cada item de `merges` ha de tenir `name`, `type`, `source_feature_maps` (llista no buida) i `output_feature_map_name`.
- No inventis inputs/targets fora dels disponibles.
- Mantén coherència de `maps_to_target_config_name`.
- `Add`/`Multiply`/`Concatenate`: `input_source_feature_maps` >=2.
- `AttentionKeras`/`MultiHeadAttentionKeras`: rank >=3.
- `TimeDistributed`: inner layer suportada.
- `Bidirectional`: requereix `wrapped_layer` o `inner_layer`.
- `Dense` requereix `units`; `Conv1D` requereix `kernel_size`; `GRU/LSTM` requereixen `units`.

### Claus prohibides (dialecte legacy)
No utilitzis aquestes claus dins `architecture_definition`:
- `inputs`
- `input_layers`
- `shared_backbone`
- `layers` a nivell arrel de `architecture_definition`

### Mini schema obligatori (V3)
`model_definition_full.architecture_definition` ha de tenir aquest patró:
```json
{
  "used_inputs": [
    {
      "input_layer_name": "...",
      "source_feature_name": "...",
      "shape": [800]
    }
  ],
  "branches": [
    {
      "name": "...",
      "input_source_layer": "...",
      "layers": [
        {"type": "Dense", "units": 64, "activation": "relu", "name": "..."}
      ],
      "output_feature_map_name": "..."
    }
  ],
  "merges": [],
  "output_heads": [
    {
      "output_layer_name": "...",
      "maps_to_target_config_name": "...",
      "source_feature_map": "...",
      "units": 1,
      "activation": "linear"
    }
  ]
}
```

Si utilitzes `merges`, cada merge ha de seguir aquest format mínim:
```json
{
  "name": "fusion_main_aux",
  "type": "concatenate",
  "source_feature_maps": ["main_features", "aux_features"],
  "layers_after_merge": [
    {"type": "Dense", "units": 64, "activation": "relu", "name": "fusion_dense"}
  ],
  "output_feature_map_name": "shared_features"
}
```
