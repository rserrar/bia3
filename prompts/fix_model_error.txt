### Capes suportades i paràmetres mínims
El model pot usar les següents capes suportades pel runtime de la V3. Cada capa ha de respectar els paràmetres mínims indicats.
- `Dense`: requereix `units`.
- `Dropout`: usa `rate`.
- `SpatialDropout1D`: usa `rate`. Per a tensors 3D.
- `AlphaDropout`: usa `rate`. Manté mitjana/variància (ideal després de SELU).
- `GaussianDropout`: usa `rate`. Soroll Bernoulli multiplicatiu.
- `ActivityRegularization`: usa `l1` i/o `l2`.
- `Conv1D`: requereix `kernel_size` i `filters`. Requereix tensor 3D.
- `SeparableConv1D`: requereix `kernel_size`, `filters` (opcional `depth_multiplier`). Variant lleugera de Conv1D.
- `LSTM` / `GRU`: requereixen `units`. Requereixen tensor 3D.
- `Bidirectional`: requereix `wrapped_layer` o `inner_layer` amb `LSTM` o `GRU`.
- `TimeDistributed`: requereix `wrapped_layer` o `inner_layer` (ex: `Dense`).
- `AttentionKeras` / `MultiHeadAttentionKeras`: requereixen tensors de rank >=3.
- ⚠️ REGLA CRÍTICA: No posis MAI `AttentionKeras` o `MultiHeadAttentionKeras` directament sobre seqüències de longitud >128 sense reduir abans amb pooling.
- `Add` / `Multiply` / `Concatenate` dins `branches[].layers[]` o `merges[].layers_after_merge[]`: requereixen `input_source_feature_maps` amb >=2 tensors.
- `merges[]`: requereixen `source_feature_maps` amb >=2 tensors.
- `MaxPooling1D` / `AveragePooling1D` / `GlobalMaxPooling1D` / `GlobalAveragePooling1D` / `Flatten`: reducció temporal.
- `RepeatVector`, `GaussianNoise`, `Masking`, `Activation`, `Softmax`, `ReLU`, `LeakyReLU`, `PReLU`, `ELU`.
- `BatchNormalization`, `LayerNormalization`, `Reshape`, `LambdaSlice`.
- `Reshape`: usa `target_shape`.
- `MaxPooling1D` / `AveragePooling1D`: si s'especifiquen, usa `pool_size`.
- `Activation`: si s'usa com a capa explícita, defineix `activation_function`.
- `MultiHeadAttentionKeras`: defineix `constructor_params.num_heads` i `constructor_params.key_dim`.
- Consulta `architecture_guide_content` per patrons vàlids de CNN, RNN, attention, residuals i fusions multi-branca.

### Errors comuns i solucions
- Si l'error és de dimensió, comprova si `Conv1D`, `LSTM`, `GRU`, `AttentionKeras` o `MultiHeadAttentionKeras` requereixen tensors de rank >=3.
- Si el model usa `TimeDistributed`, comprova que el `wrapped_layer` o `inner_layer` sigui una capa suportada i vàlida.
- Si el model usa `Bidirectional`, comprova que el `wrapped_layer` o `inner_layer` sigui `LSTM` o `GRU`.
- Si el model usa `Add`, `Multiply` o `Concatenate` dins una capa, comprova que `input_source_feature_maps` sigui una llista amb almenys 2 tensors vàlids.
- Si el model usa `merges`, comprova que cada merge tingui `source_feature_maps` com a llista no buida.
- Si el model falla per incompatibilitat d'inputs, mantén `used_inputs` amb els noms i shapes exactes de `available_inputs_contract_json`.
- Si el model falla per `output_heads`, mantén `maps_to_target_config_name` i `units` segons `available_outputs_contract_json`.
- Si hi ha dubte entre noms antics i nous, usa exclusivament els noms d'`available_inputs_contract_json` i `available_outputs_contract_json`.
- Si l'error diu `incompatible shapes` en `Add` o `Multiply`, no forcis el merge: iguala dimensions amb una projecció compatible (`Dense`, `Reshape`, pooling, o simplifica el wiring) abans d'intentar combinar tensors.
- Si l'error diu que `MultiHeadAttentionKeras` o `AttentionKeras` no tenen fonts d'entrada, afegeix `input_source_feature_maps` amb 1-3 mapes vàlids segons el cas.
- Si una branca amb `Conv1D`, `LSTM`, `GRU` o attention rep un tensor 2D, afegeix `Reshape` o reusa un feature map 3D compatible en lloc d'improvisar capes noves.
- Si hi ha dubte de wiring, prefereix una reparació conservadora: elimina només el bloc defectuós o substitueix-lo per un patró equivalent més simple però compatible.

### Guardrails d'arquitectura
- `architecture_definition` obligatori.
- `used_inputs` obligatori i no buit.
- `branches` obligatori i no buit.
- `output_heads` obligatori i no buit.
- `Dense` requereix `units`; `Conv1D` requereix `kernel_size`; `GRU/LSTM` requereixen `units`.
- `Add`/`Multiply`/`Concatenate` dins capes requereixen `input_source_feature_maps` >=2.
- Si existeix `merges`, cada merge ha de tenir `source_feature_maps` (llista no buida).
- `AttentionKeras` i `MultiHeadAttentionKeras` dins capes requereixen `input_source_feature_maps` no buit.
- No barregis `input_source_feature_maps` i `source_feature_maps` al mateix objecte.
- Si la capa és `Add` o `Multiply`, les entrades han de tenir la mateixa forma; si la capa és `Concatenate`, només poden diferir a l'eix de concatenació.
